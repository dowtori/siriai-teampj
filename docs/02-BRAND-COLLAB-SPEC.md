# 브랜드 명단 검토 · 소통 — 기획

> 관련: [01-BRAND-REPORT.md](01-BRAND-REPORT.md) — 보고서 수집 기술 검토

---

## 왜

지금은 이렇게 돕니다.

```
명단을 시트로 만든다 → 카톡·메일로 보낸다 → 답을 기다린다
→ 회신을 시트에 옮겨 적는다 → 대체 인원을 다시 찾는다 → 다시 보낸다
```

문제는 세 가지입니다.

- 어떤 인원이 왜 반려됐는지가 **대화 속에 흩어집니다.** 다음 캠페인에 재사용되지 않습니다.
- 브랜드가 지금 몇 명까지 봤는지 **알 수 없습니다.**
- 시트와 대화가 어긋나면 **어느 쪽이 맞는지** 확인해야 합니다.

브랜드 페이지 안으로 옮기면 셋 다 없어집니다.

## 흐름

```
어드민                          브랜드 페이지
──────                          ────────────
후보 명단 담기
검토 요청 보내기      ──────▶    검토 대기 알림 (이메일)
                                 인원별 승인 / 보류 / 제외
                                 인원별 메모 · 전체 코멘트
검토 결과 도착 알림   ◀──────    제출
담당자 답변           ──────▶    답변 알림 (이메일)
확정                  ──────▶    확정 명단 공유
캠페인 진행
```

한 캠페인에 **회차가 여러 번** 생깁니다. 1차에서 반려된 자리를 채워 2차를 보냅니다.

## 데이터 구조

기존 `campaign_participation` 은 그대로 두고 **위에 얹습니다.**
브랜드가 승인한 인원만 실제 참여로 내려갑니다.

```
selection_round            제안 회차
  campaign_id
  round_no                 1차 · 2차 …
  status                   작성중 / 발송 / 검토중 / 제출됨 / 확정
  sent_at, due_at, closed_at

selection_item             회차에 담긴 인원
  round_id
  participation_id         → campaign_participation
  proposed_fee             제안 단가
  brand_decision           대기 / 승인 / 보류 / 제외
  brand_note               브랜드 메모
  agency_reply             담당자 답변
  decided_at

thread                     소통 단위
  campaign_id
  scope                    캠페인 전체 | 인원 개별
  item_id                  scope 가 개별일 때

message
  thread_id
  author_type              대행사 | 브랜드
  author_name
  body, created_at, read_at
```

### 반려 사유를 자산으로

`brand_decision` 과 `brand_note` 가 쌓이면 다음 캠페인에서 씁니다.

```
"이 브랜드는 팔로워 5천 이하를 세 번 반려했다"
"이 인플루언서는 A 브랜드에서 제외됐지만 B 브랜드에서 두 번 선정됐다"
```

지금은 이게 전부 카톡 속에 있어 사라집니다.

## 브랜드 화면

### 명단 검토

카드 그리드. 카드마다 프로필 · 지표 · **우리와 함께한 이력**.

```
┌─────────────────────────────────────┐
│ ◯ beureyu   수비니                   │
│   94,730 팔로워 · ER 3.2% · 뷰티     │
│   함께한 캠페인 3회 · 업로드율 100%   │
│   제안 단가 ₩1,900,000               │
│                                      │
│  [ 승인 ]  [ 보류 ]  [ 제외 ]         │
│  ┌────────────────────────────────┐  │
│  │ 메모를 남겨주세요                │  │
│  └────────────────────────────────┘  │
└─────────────────────────────────────┘

하단 고정 ─────────────────────────────
 승인 18 · 보류 3 · 제외 2 · 대기 7
                    [ 검토 결과 보내기 ]
```

- 정렬 — 팔로워 / 단가 / 협업 이력
- 필터 — 카테고리 / 팔로워 구간 / 처음 제안 vs 재협업
- 저장 — 자동. 브랜드가 나갔다 와도 그대로

### 소통 패널

우측 하단 상시 노출. 캠페인 전체 대화와 인원별 대화가 한 곳에 모입니다.

```
┌────────────────────────┐
│ 담당자와 대화        ✕ │
├────────────────────────┤
│ 전체 · beureyu(1)      │
├────────────────────────┤
│  담당자                 │
│  1차 명단 보내드립니다   │
│                  14:20 │
│                        │
│         브랜드          │
│    5천 이하는 빼주세요   │
│  14:35                 │
├────────────────────────┤
│ [ 메시지 입력       ▶ ] │
└────────────────────────┘
```

브랜드는 로그인이 없으므로 **코드가 곧 신원**입니다.
담당자 답변은 이메일로도 나가서, 페이지에 다시 안 들어와도 알 수 있습니다.

## 어드민 화면

| 화면 | 내용 |
|---|---|
| **검토 현황** | 회차별 진행률 · 브랜드가 아직 안 연 건 · 마감 임박 |
| **받은 의견** | 보류 · 제외된 인원과 사유를 한 화면에. 대체 인원 바로 담기 |
| **소통함** | 브랜드별 미응답 스레드 |

받은 의견 화면에서 **제외 → 대체 인원 담기 → 2차 발송**까지 한자리에서 끝나야 합니다.
지금 이 과정이 시트와 카톡을 오가느라 가장 오래 걸립니다.

## 알림

| 상황 | 대상 | 채널 |
|---|---|---|
| 검토 요청 발송 | 브랜드 담당자 | 이메일 |
| 마감 임박 (D-1) | 브랜드 담당자 | 이메일 |
| 검토 결과 제출 | 우리 담당자 | 어드민 알림 + 슬랙 |
| 담당자 답변 | 브랜드 | 이메일 |
| 확정 | 양쪽 | 이메일 |

브랜드는 알림톡 대상이 아닙니다. 이메일로 충분합니다.

---

## 만들지 않는 것

범위를 분명히 해둡니다.

- **브랜드 계정 · 로그인** — 코드로 충분합니다
- **실시간 채팅** — 메시지는 새로고침이나 폴링으로 족합니다
- **파일 첨부** — 1차에서는 텍스트만
- **승인 결재선** — 브랜드 내부 승인 절차는 우리 관심사가 아닙니다

---

## 결정이 필요한 것

1. **최종 결정권** — 브랜드가 제외한 인원을 우리가 다시 넣을 수 있는지
2. **단가 공개** — 브랜드에 인원별 제안 단가를 보여줄지 (지금 브랜드 페이지는 전부 가림)
3. **검토 기한** — 기한을 걸지, 걸면 지났을 때 어떻게 할지
4. **여러 담당자** — 브랜드 쪽에서 여러 명이 볼 때 누가 결정하는지
