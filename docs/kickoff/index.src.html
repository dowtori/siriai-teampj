01

내부 운영 리소스 효율화

손으로 옮겨 적는 일을 없앤다

  • 지금은 캠페인 하나를 두고 마스터시트 · 진행시트 62탭 · 검수시트 · 슬랙 · 드라이브를 오갑니다.
  • 같은 값을 사람이 여러 번 옮겨 적습니다 — 값이 옆 칸으로 밀린 행이 276건 나왔습니다.
  • 오늘 할 일 한 화면에서 마감 · 리마인드 · 검수 · 정산을 체크로 끝냅니다.
  • 검수는 캠페인 안에서 건별로 합니다. 30건을 한 번에 통과시키거나 같은 사유로 되돌립니다.
  • 슬랙에서 하던 대화를 캠페인에 붙입니다 — 담당자를 부르고 할 일로 추적합니다.
02

고객사 경험 개선

시트 대신 고객사 화면에서 본다

  • 지금은 진행시트 링크를 열어 보여드립니다. 보여드릴 것과 아닌 것이 같은 파일에 있습니다.
  • 접근 코드로 들어와 자기 캠페인만 봅니다. 모집 → 컨펌 → 업로드 → 계산서 → 정산 6단계로 지금 어디인지 보입니다.
  • 선정 인원을 사진 고르듯 골라 컨펌합니다. 목록 · 3×3 · 5×5 로 바꿔 봅니다.
  • 올라온 콘텐츠가 링크가 아니라 화면에 그대로 박힙니다.
  • 컨펌이 밀리면 어디서 막혔는지 우리 쪽에서도 같은 화면으로 보입니다.
03

시스템 자산 확보

DECISIONS

착수 전 결정

결정 내용에 따라 구현이 달라지는 항목입니다.

BLOCKING
  1. 캠페인 진행 단계 확정 — 시트에는 종료 · 상시 두 가지만 실제로 쓰이고 있어, 프로토타입은 모집 → 컨펌 → 업로드 중 → 업로드 완료 → 계산서 발행 → 정산 완료 6단계를 입금상태 · 계산서일에서 역산해 쓰고 있습니다. 지금은 브랜드 6단계 · 어드민 보드 5레인 · 인플루언서 4단계로 축이 셋으로 갈라져 있습니다. 이 6단계를 확정하고 세 화면의 축을 하나로 합치는 것이 결정 대상입니다.
  2. 시트 전환 방식 — 완전히 옮기기 / 시트는 보기 전용으로 남기기 / 양쪽 계속 맞추기. 양쪽을 계속 맞추는 건 30일 안에 불가능합니다.
  3. 정산 범위 — 계산서 발급까지 시스템이 하는지, 발급일과 금액만 기록하는지.
  4. 인플루언서 정산자료 — 주민등록번호 · 통장사본을 시스템이 받는지. 받으면 원천징수 로직과 암호화 저장이 범위에 들어옵니다.
  5. 어드민 로그인 방식 — 회사 구글 계정 / 따로 만든 계정 / 초대받은 사람만. 내부 인원 수와 권한 등급.
DESIGN IMPACT
  • 브랜드 페이지 공개 수준 — 광고 랜딩 겸용이면 코드 게이트를 어떻게 우회시킬지.
  • 일본어 지원 — 인플루언서 풀의 38%가 일본입니다. 틱톡 풀은 사실상 일본 전용입니다.
  • 원본 갱신 방식 — 수동 재업로드인지 연동인지, 주기는 어떻게 되는지.
  • 기존 siriai-sales와의 관계 — 흡수 통합 / 별도 유지 / 리다이렉트.
  • 주소 구조 — 주소를 나눌지(admin.siriai…) 경로로 구분할지(siriai…/admin).

리스크

착수 전 확인된 항목

R1
같은 사람인지 못 알아봄

표시 이름이 제각각이고 계정 주소 표기도 통일되어 있지 않습니다. 판별에 실패하면 협업 경험 명단 자체를 만들 수 없습니다. 계정 주소 형식 통일과 사람이 직접 합치는 화면을 1주차에 함께 넣습니다.

R2
개인정보 노출

현재 검수시트에 실명 · 연락처 · 자택 주소가 평문으로 있습니다. 암호화와 열람 제한은 데이터 구조를 짤 때 넣어야 하며, 이후에는 붙이기 어렵습니다.
